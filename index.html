Welcome to ChronoRET, a byte-exact matching decompilation of Chrono Trigger (SNES, US 1.0).

The goal is hand-labeled 65816 assembly that assembles back to a ROM that is bit-for-bit identical to the original 1995 cartridge. A routine only reaches the main branch once it is matched byte for byte, written to the project's readability standard, and approved by an independent review.

This project is not affiliated with or endorsed by Square or Square Enix in any way.

Project at a glance

Bank What is matched there
$C0 The field engine: game loop, frame wait and NMI handler, location loading, map scrolling, object motion, the event script opcodes, the sprite system, and the reset code, header and vectors at the top of the bank
$C1 The battle engine: BattleSys_Main and its turn lists, the enemy behaviour scripts, the PC command runner, action scripts, the battle menu, targeting and status bar
$C2 The scene mode (tasks, scripts, sprite list, scene loading) and the text window decoder
$FD MainInit, the battle helpers bank $C1 calls with JSL, the field HDMA set-up and the location animation set-up
$CC, $CF, $FF Copies of matched code kept in other banks: the 8×8 multiply ($CC), a scaled sine and a four-digit number formatter ($CF), the wave tables ($FF)

How much of each bank is matched, and at which level, is generated on the ROM Map and Progress pages.

Reference

Matched regions

What is matched, bank by bank, is on the ROM Map, generated from the code repository on every update, so it is never out of date. The figures by level, bank and day are on Progress, and every routine of a system is listed on its page under Systems.

The 4 MB ROM is mostly graphics and music data; only about 359 KB is executable 65816 code.

Methodology

A routine goes through these steps before it reaches the main branch:

  1. Draft — make draft ADDR=C1:3714 (tools/draft.py) disassembles the routine from its address, tracking the M/X flags, DP and DB, and writes asar source that already uses every name the project has for its operands. It checks that the draft assembles to the original bytes.
  2. Make it readable — the matcher names what the draft could not (RAM, constants, calls, the routine itself) and writes the header: what the routine is for, its CPU state on entry and exit, and anything a reader would not guess. Unknown meanings stay hedged ("probably", Unk names).
  3. Gate — make gate runs the byte-for-byte diff (make diff), proves that every byte the source claims is really emitted by it (make verify), and runs the readability lint (tools/lint_readability.py). The ; Callers block of each header is generated by tools/callers.py, never written by hand.
  4. Review — someone who did not write the routine checks that its names and comments tell the truth. The verdict is a row in a review round file (symbols/reviews/rNNN.csv) that carries the routine's source hash, so any later edit sends it back for review.

Each level includes the one before: matched → readable → verified. The figures are computed by tools/progress.py from the source and the review log; generated files are not committed, and no number is typed by hand.

Legal

Tools and source only — no ROM data, no extracted assets. To contribute or verify matches you need your own legally obtained copy of Chrono Trigger (SNES, US 1.0).
