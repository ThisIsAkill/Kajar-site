How the cartridge is laid out

The US 1.0 cartridge is a 4 MB HiROM board: 64 banks of 64 KB, $400000 bytes in all. The CPU can see the same ROM bytes at several addresses:

CPU banks What they show
$C0–$FF The whole 64 KB of every ROM bank. These are the canonical addresses this wiki uses.
$40–$7D The same banks again, minus the last two: $7E–$7F are work RAM instead.
$00–$3F The upper half ($8000–$FFFF) of each bank; the lower half is RAM and hardware registers.
$80–$BF A mirror of $00–$3F, used to select the faster ROM access speed.

So $C0:FF00 and $00:FF00 are the same byte, which is why the reset code, the internal header and the interrupt vectors at the top of bank $C0 are often written with bank $00. A file offset is (bank − $C0) × $10000 + address: $C1:0089 is at 0x010089 in the ROM file.

Only about 359 KB of the 4 MB is 65C816 code; the rest is graphics, music, maps and text, built from the original bytes. The code size of each bank comes from a one-off survey of a reference disassembly, which marked every byte as code or data.

The engine's spine: the reset code and interrupt vectors at the top of the bank, the game loop, the VBlank handler, scene loading and the sprite system. Most of what has been matched so far falls into a few self-contained groups:

  • Game loop ($C0:000E–$011A): one-time start-up, then the per-frame loop. See the structure below.
  • Per-frame state machine ($C0:0C76–$2DF0): called every frame from the game loop. It drives the door and switch tile-opening animations through the mode handlers (ModeE6, ModeEC, ModeEE, ModeFA, ModeFC and the default path), which advance the $7E:3000 tile table, compute VRAM write indices corner by corner and trigger sound cues. The screen-transition gate Sub_18D9 and its callees run the full scene-transition sequence. Sub_885A, a large routine called from the default handler, is traced but not matched yet.
  • Sprite rendering ($C0:B271–$C989): PostVBlank walks the sprite table every frame and hands each entry to the renderer for its type.
  • Animation tick and queue ($C0:C98A–$CB09): per-frame animation timers and the queue the VBlank handler drains.
  • Sprite-slot set-up ($C0:CB0A–$E129): a dispatcher picks the routine for the sprite's type (bits 0–1 of $1201,X); each routine gates on the animation frame, claims one, two or three slots from the allocators at $E952–$E9E1, then copies 8 or 16 tiles to work RAM, several passes for the large sprites.
  • Scene sprite load ($C0:E12A–$E934): run once per sprite slot during scene load. For each of 96 entries, bit 14 picks either a lookup through a table in bank $FD or a tile copy from one of banks $D2–$D5 or $7F.
