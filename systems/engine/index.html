Engine core

Bank $C0's field engine: the game loop and its per-frame calls, location loading, the map (collision, tile effects, scrolling and redraws), the field's scene changes and its hand-off to the battle and to bank $C2, window effects, the staff credits, and the object motion code. Three parts have pages of their own: Frame cycle and NMI, Field event scripts and Sprites & objects.

The field code runs with DP=$0100 (the field page, names in asm/include/ram_engine.inc) and DB=$00; the map code switches to DP=$1D00 (!DP_Map). The function table at the bottom of this page lists every routine in the "Engine" group, which also takes in the matched code of banks $C2 and $FD that has no group of its own; "Engine (unnamed)" holds the two routines still labelled Sub_: Sub_1ADF (purpose unknown) and Sub_C07F9A (no reader of its results traced).

See also: Architecture, Boot, Sprite Init Explainer, ROM Map.

The game loop

GameLoop_LoadField ($C0:007D) loads a location and falls into GameLoop_FrameBody ($C0:0097), which runs, every frame: Field_PauseAndMenuInput, Field_SceneChangeTick, Field_FrameUpdate, Field_ActionButton, Field_Unk1F87 (the message window's step; see Field event scripts), Field_EventHookDispatch, Field_ServiceUnk54, Field_EndOfFrame and Field_WaitFrame. See Architecture for the order and Frame cycle and NMI for the end of the frame.

  • Field_PauseAndMenuInput ($C0:18D9): Start pauses (the brightness halves until Start is pressed again); the menu button fades out, saves the field and calls bank $C2's menu entry ("very likely the main menu", per its header).
  • Field_FrameUpdate ($C0:881E): with DP=$1D00, the D-pad (Field_DpadDispatch and its 16-entry table), the leader's collision (Map_Unk8A6D, probably), the step limits and the layer scroll (Map_Unk91AC, Map_Unk93E1).
  • Field_ActionButton ($C0:1AAC): on the action button, looks for an object in front of the leader (Field_FindObjInFront) and starts its function 1, then checks the tile in front for treasure (Field_CheckTileInFront).

Loading a location

LoadLocation ($C0:00F4) runs ten steps and two bank-$FD vectors:

Step Does
LocLoad_Unk092B Find the location's record (LocRom) from Loc_Id
LocLoad_AudioSetup The sound step
LocLoad_Unk0960 Layers 1 and 2 graphics
LocLoad_Unk6DCF Layer 3 graphics (or none)
LocLoad_Unk7084 The location's palette rows
LocLoad_ClearPage1D00 Zero the map page
LocLoad_UnkA33B Map properties: layer sizes and screen settings, then the wrap masks and limits, the tile planes and the exit tiles
LocLoad_Unk09DD, LocLoad_Unk0A14 The layer 1/2 and layer 3 metatile tables
LocLoad_Unk56D4 Unpack and check the event data
FdVec_FFFA, FdVec_FFF4 Location animation set-up (FieldFD_LoadAnimSetA/B): records at $05B0 and $0520, probably the tile and palette animations

Then Scene_PostLoadInit ($C0:56A6) resets the object tables and runs every object's init script, and Scene_SettleFrames runs Scene_ReloadStep ($C0:286C: draw the map with LocLoad_DrawMap, reset the objects, the uploads and palettes, NMI back on) and fades in. Most steps keep Unk names because verified callers use them; NEXT.md lists the better names waiting for those callers' next review.

The map

The map is kept in WRAM as metatiles; the map code runs with DP=$1D00.

  • Collision and tile effects ($C0:8A6D–$C0:9174, $C0:9923–$C0:9DC2): Map_Unk8A6D tests the frame's step against the leader's box with probes for other objects (Map_ProbeHitsObj) and for the map tile under a point (Map_ProbeTileAttrs, Map_ProbeTileLevel, Map_ProbeLevelBlocked), and slides along walls. Map_StepTileEffects commits a kept step: an exit tile requests a warp (from the ExitRom records in bank $E5, "inferred: an exit tile"), a tile with attribute bit 4 requests a tile animation, and the tile's level and push are applied. Map_InitEntryTile is its sibling at load time.
  • Scrolling ($C0:91AC–$C0:9922): Map_Unk91AC adds up the frame's scroll amounts for three sets of layer scroll words in 1/16 pixel (with a scroll-to target and a screen shake) and splits out whole pixels; Map_Unk93E1 steps the words a pixel at a time and notes each 8-pixel boundary crossed. The 16 edge builders Map_BuildRow* / Map_BuildCol* ($C0:8243–$C0:8444) build the new row or column, and the NMI uploads it (Map_UploadRowYInc1 …).
  • Redraws ($C0:75E9–$C0:8242): whole-layer redraws into the $7E:C800 buffer (Field_BuildC800Mode1/2/4), the row and column writers, and the VRAM uploads (Map_UploadBuf*), driven by DefaultHandler's redraw request and Field_Unk885A.
  • Tile animations: the five handlers ModeE6_Handler … ModeFC_Handler ($C0:0D78–$C0:16DB) advance a map tile's state byte and queue the VRAM addresses of its 8×8 tiles for doors and switches that open over a few frames (see Architecture). The field IRQ writes the new tilemap words (see Frame cycle and NMI). TileAnimList (16 words at $7F:1CC8, $C0:28AA–$C0:29F6) remembers the tiles whose animation ran at this location, so that a reload (Scene_ReloadStep) puts their final states back into Map_TileProps before the map is drawn.

Scene changes, fades and hand-offs

Field_SceneChangeTick ($C0:0C76) and DefaultHandler ($C0:16DC) act on the scene request bits: warp, bank-$C2 call, tile animation, single tile step, map redraw and battle (see Architecture). The fades are Fade_StepBrightness and Fade_StepFixedColor ($C0:1F24, $C0:1F5A).

  • Bank $C2 round trips: Field_SaveState / Field_RestoreState ($C0:011B, $C0:01A5) save and rebuild the field around a call to BankC2_Entry8000, with Field_StashSaveBlock / Field_RestoreSaveBlock copying the $14E0-byte save block to $7F:2000 and back.
  • Battle hand-off ($C0:0283–$C0:0904): before a battle Field_Unk038F fills the hand-off block (FieldBtlPc, FieldBtlObj, FieldBtlPpu at $7E:29B0–$2C7B) with the party's positions, the objects and the PPU state; afterwards Scene_Unk0283 reads FieldBtl_Result and rebuilds in place (FieldBtl_Restore), reloads the location, or restarts the game (probably the game-over path).

Services for other banks

ReentryVectors entries 1–4 ($C0:0002–$C0:000B) are JSL targets for code in other banks (the calling sites are in banks $CD and $D1, not matched):

  • ScrollStepAccum ($C0:2C41): steps the scroll positions of layers 2 and 3 by signed per-frame speeds in 1/16 pixel and stores them into the battle hand-off's FieldBtlPpu.Scroll2 words; its header suggests the name LayerDrift_Step, "probably the battle backgrounds' drift". DefaultHandler calls it too.
  • Field_RefreshHdmaLong ($C0:0AFF, formerly the stub AudioDrvSync; it touches no sound): runs EngFD_UnkC2C1 twice, so both of its handler tables run once, sets up the HDMA channels and returns the HDMA channel mask.
  • MusicCueDispatch ($C0:1BAB): "before a battle, probably". With FieldBtl_EvtKeepMusic clear it sends sound command $14 with a track ($45 at load, "the battle music, probably"); with it set, command $70.
  • AudioFadeDispatch ($C0:1BE6): "after a battle, probably", by FieldBtl_Result. Result 1 ("the party lost, probably") sends command $14 with song $26; otherwise, unless FieldBtl_EvtKeepMusic is set, it sends command $11 with Menu_Config1E (where Evt_OpEA_PlayMusic keeps the track it starts). It restores DB and D in the wrong order, which is harmless only when the caller has D = 0 and DB = 0; kept as found.

Window effects and credits

  • Field_EventHookDispatch ($C0:21E1) runs one of 16 hooks from Field_EventHookTable: growing and shrinking window shapes on the BG or colour windows, a shape from four moving points, fixed shapes, a pulsing shape that runs its own frames, and a hook that leaves the field for good (Field_HookLeaveToBankC3).
  • Field_ServiceUnk54 ($C0:274D) builds the staff credits a line at a time from the text at $FD:A000 (the NMI sends each line with Credits_UploadLine), and passes map redraw requests on to the NMI.

Objects

The per-frame object pass Vblank_UnkA810 ($C0:A810) moves every object (Obj_MoveStep, Obj_MoveStepFree), tests it against a window a little larger than the view (Obj_UpdateInView), ticks its animation and puts it in the draw bucket for its screen position. Obj_CalcDirection, Obj_SetVelocity and Obj_SetVelocityChecked ($C0:ABA2–$C0:AF2F) set up moves for the event opcodes. The party members' objects step through Evt_OpB0_PartyControl's callees ($C0:9E29–$C0:A33A): the leader's step (Party_Unk9E29) logs each frame it moves in a 128-entry ring in bank $7F, and members 2 and 3 (Party_UnkA26B, Party_UnkA2CE) replay it $18 entries behind the one ahead ($10 when the leader stands), so they walk the leader's path. Each picks its facing and animation row (walk, run, stand or idle) from the step through Party_AnimTable ($C0:9FF7, 65 words). Positions are in 1/16 pixel; the high byte is the 16-pixel map tile. The tile-slot and palette-slot allocators (Obj_TileSlot*, Obj_PalSlot*, $C0:6F9A–$C0:7083, $C0:7170–$C0:7398) give objects VRAM and palette space by kind. See Sprites & objects for drawing.

Bank $FD field code

The field HDMA set-up (EngFD_UnkC124, Hdma_InitChannelsFD, EngFD_UnkC2C1 with its two handler tables, $FD:C124–$FD:C2EA, and EngFD_UnkD52D), and the location animation set-up (FieldFD_LoadAnimSetA / B and the vectors FdVec_FFF4 / FFF7 / FFFA).

What is not matched yet

From NEXT.md, the last unmatched code in bank $C0 is Irq_UnkF05E ($C0:F05E–$C0:F10F, run by the IRQ while Field_Unk63 is not negative; the choice cursor, probably) with its callees, then whatever follows up to $C0:FCFF ("not looked at: data, probably"). In bank $FD: the IRQ's other phase FdVec_FFFD, the HDMA builders behind EngFD_UnkC2C1's tables, and EngFD_UnkE39C (FdVec_FFF7's target).
