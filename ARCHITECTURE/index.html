Engine Architecture

A high-level map of the Chrono Trigger SNES engine as recovered from matched code. Everything here is verified — it comes from byte-exact matched routines, not guesswork.

Boot sequence

Power-on / RESET vector ($00:FF00)
  └─ Reset (7 bytes)
       SEI / CLC / XCE        native mode on
       JML MainInit            jump to bank $FD

$FD:C000 — MainInit (215 bytes)
  ├─ CPU: SEI, native mode, DP=0, DB=0, SP=$01FF
  ├─ PPU: forced blank, zero all PPU registers
  ├─ APU: boot SPC700 with silent init payload
  ├─ WRAM: DMA zero-fill all 128KB via ClearRAMDMA stub address
  └─ JML GameLoop              jump to bank $C0

Game loop

$C0:000E — GameLoop (one-shot startup)
  ├─ JSR ClearRAMDMA ($C0:2DF1)   zero-fill WRAM via DMA
  ├─ JSR InstallNMI ($C0:0B64)    write JML $C0:EA63 → $7E:0500
  ├─ JSR InstallIRQ ($C0:0B75)    write JML $C0:ECCC → $7E:0504
  └─ falls into GameLoop_Main

$C0:005D — GameLoop_Main (per-mode outer loop)
  ├─ JSR FrameStateInit ($C0:0B86) reset per-frame state
  ├─ LDA/STA mode dispatch on $0100
  ├─ enters GameLoop_FrameBody
  └─ loops back

$C0:0097 — GameLoop_FrameBody (tight per-frame inner loop)
  ├─ JSR $C0:881E    (unknown — possibly DMA trigger)
  ├─ JSR Sub_0C76    (door/switch tile-opening dispatch + scene transition gate)
  ├─ JSR Sub_18D9    (screen-transition gate: fade, reinit, scene context save/restore)
  ├─ JSR $C0:1AAC    (unknown)
  ├─ JSL $C0:1F87    (cross-bank — possibly audio)
  ├─ JSL $C0:21E1
  ├─ JSL $C0:274D
  └─ BRL → VBlankHandler / loops

VBlank handler

$C0:00BF — VBlankHandler (per-NMI, each frame)
  ├─ JSR $C0:881E    (shared with frame loop)
  ├─ audio/DMA work
  └─ BRL PostVBlank  (tail call — no RTS; returns to VBlankHandler's caller)

$C0:00DE — VBlankHandlerShort (minimal path, no audio)
  └─ RTS

$C0:B271 — PostVBlank (152 bytes, matched)
  ├─ Reset OAM hardware DMA channel registers
  ├─ Walk sprite descriptor table ($7E:0E00, 63 entries × 2 bytes)
  │    for each active entry: JSR Sub_B309 (build OAM buffer slot)
  │    follow chain links until chain byte < 0 (end marker)
  ├─ Fill unused OAM slots with Y=$E0 (off-screen)
  └─ RTS

$C0:B309 — Sub_B309 (1016 bytes, matched)
  ├─ JSR Sub_B701 → BCC skip  (gate: skip if sprite not ready)
  ├─ LDX $6D / LDA $1201,X / AND #$03 → sprite type dispatch (0/1/2/3+)
  │
  ├─ Each type path:
  │    PHD / REP #$20 / LDA #$2100 / TCD / SEP #$20   (DP=$2100 trick)
  │    LDA $0F80,X / AND #$0C → OAM range dispatch (bits 2-3)
  │
  ├─ Range dispatch (per type, 3 sub-paths):
  │    Range 1 (bits 2-3 = 00): OAM write-head at $0181, WRAM dest at $01DB
  │    Range 2 (bit 2 set):     OAM write-head at $0185, WRAM dest at $01DD
  │    Range 3 (bit 3 only):    OAM write-head at $0189, WRAM dest at $01DF
  │
  ├─ OAM write per type (from bank $7F staging buffer → OAM slot):
  │    type 0: 1 byte  (LDA.l $7F4F00,X → STX $0181 range → STA.w $0000,X)
  │    type 1: 2 bytes (LDA.l $7F4F01,X / PHA / LDA.l $7F4F00,X → write pair)
  │    type 2: 3 bytes (LDA.l $7F4B40,X / PHA / $7F4F01,X / PHA / $7F4F00,X)
  │    type 3+: 6 bytes (5×PHA + 1 in A, from $7F4F81/$7F4F80/$7F4B41/$7F4B40/$7F4F01/$7F4F00)
  │
  ├─ WRAM dest advance (per type):
  │    LDX $01DB / STX $81 (→ WMADDL=$2181 via DP=$2100 trick)
  │    REP #$20 / LDA $01DB / CLC / ADC #$0010 (or $20/$30/$60) / STA $01DB
  │
  ├─ Shared gfx+palette loop (per type, all 3 ranges converge here):
  │    LDA $1700,X → TAX  (sprite gfx index, 16-bit)
  │    LDA #$04 (or $08/$0C/$18) → STA $01C9  (palette loop counter)
  │    loop: LDA.l $7F4BC0,X / STA $80 (WMDATA via DP trick) ×4 per iter
  │           REP #$20 / TXA / CLC / ADC #$0008 / TAX / SEP #$20
  │           DEC $01C9 / BNE loop
  │
  └─ PLD / RTS

$C0:B701 — Sub_B701 (135 bytes, matched)
  (see below)

Per-frame reset

$C0:0B86 — FrameStateInit (240 bytes, matched)
  ├─ Save sprite registers ($00/$02/$04) → ($0A/$0C/$0E)
  ├─ STZ ~25 per-frame flags ($10, $11, $17, $18, $38, etc.)
  ├─ Set defaults: sprite Y=$E0, OAM write-head limits
  │    $7D=$0900 / $7F=$0770 / $7B=$08A0
  ├─ Set palette defaults: $B1/$B4/$B7/$BA=$E4
  ├─ REP #$20 → 16-bit A section:
  │    STZ $2B / STZ $0150 / STZ $58
  │    LDA.l $E4FFE0/$E2/$E4/$E6 → STA $AF/$B2/$B5/$B8  (ROM seeds)
  │    STA.l $7E:2000 = 0
  ├─ SEP #$20 → 8-bit A:
  │    STA #$80 → $97/$99/$9B/$8D/$8E/$8F/$91/$90/$92/$93
  │    LDA.l $7E:2980/$81/$82 → $94/$95/$96  (WRAM color vars)
  │    STA $EB=$AE=$80 / $55=$01 / $FC=$53 / $FB=$65 / $FA=$45
  │    STA.l $7E:2989 = 0
  │    STA $0BD9/$0BDA/$0BDB/$0BE9 = 0
  │    LDA $0400 → STA $F8    (scene entry point)
  └─ RTS

RAM-resident handlers

NMI and IRQ handlers live in WRAM, installed at boot:

WRAM addr Installed by Target Purpose
$7E:0500 InstallNMI JML $C0:EA63 Real NMI handler (unmatched)
$7E:0504 InstallIRQ JML $C0:ECCC Real IRQ handler (unmatched)

This pattern allows the game to swap handlers at runtime without patching ROM.

Key data structures

Sprite descriptor table ($7E:0E00, 63 entries × 2 bytes): - Byte 0: sprite type index (negative = inactive slot) - Byte 1: chain link (index of next sprite in chain, negative = end) - PostVBlank walks this table each frame to build the OAM buffer

OAM buffer ranges (in WRAM): - Range 1: $7B–$08A0 (pointer stored at $7B) - Range 2: $7D–$0900 (pointer stored at $7D) - Range 3: $7F–$0770 (pointer stored at $7F) - Filled with Y=$E0 for unused slots to hide off-screen

Per-frame dp variables (DP=$0100 in game loop):

dp WRAM Width Contents
$00 $0100 16-bit Active sprite X position
$02 $0102 16-bit Active sprite Y position
$04 $0104 8-bit Active sprite attribute
$0A $010A 16-bit Saved previous-frame sprite X
$0C $010C 16-bit Saved previous-frame sprite Y
$0E $010E 8-bit Saved previous-frame attribute
$17 $0117 8-bit Per-frame flag (branch key in $C0:0C76)
$18 $0118 8-bit Per-frame flags (bits 2/8 tested for JSR targets)
$19 $0119 8-bit Scene transition counter
$6D $016D 16-bit Current sprite descriptor index (PostVBlank loop var)
$97 $0197 8-bit Palette seed index (default $80)
$F8 $01F8 8-bit Scene entry point (from $0400)

Sprite render/init cluster

Calls from Sub_B309 → Sub_B701 → per-type init and render routines:

Sub_B701 type 0:
  positive state → JSR Sub_B8CA (init helper 1) → JSR Sub_E9E2 (init helper 2)
  negative state → JSR Sub_B788 (renderer)

Sub_B701 type 1:
  positive high-state → JSR Sub_BCDC (high-state init) → JSR Sub_E9FF (init pass 2)
  negative low-state  → JSR Sub_BA65 (low-state init)

Sub_B701 types 2/3+:
  low-state (neg) → JSR Sub_BFF2 (12-tile low-state init; BMI-split pos path; BCS/BPL type-3+ path)
  high-state (pos) → JSR Sub_C2BF (12-tile high-state init; BPL/CMP/BCS pos path, no BMI-split; raw→staging copies)

Sub_B701 type 3+:
  BRL Sub_C73A (renderer, 6-tile)
  Sub_C73A calls Sub_C6E7 ×6 (X-pos helper, 4 tiles each)

Y-dispatch 3-way patterns — NOT uniform across routines

All matched routines with Y-clamp logic share the same logical structure — dispatch on $C6 first, then on the sign of $C5 — but use different branch mnemonics and clamp conditions in each path. Do not assume a pattern from one routine applies to another. Verify each branch byte explicitly.

Routine C6=0 dispatch (on C5) C6≠0 clamp logic C6=0 neg clamp C6=0 pos clamp Tiles
Sub_B788 BPL → positive BCS→clamp, BMI→clamp BPL+4/BCS+2 BPL+4/BCS+2 8
Sub_B8CA BPL → positive BCC→clamp, CMP/BCS→store BCC+6/BCC+2 BPL+6/BCS+2 8
Sub_C73A BMI → no-clamp BCS→clamp, BPL→store BPL+2/BCS+2 BPL+2/BCS+2 24
Sub_BA65 BPL → positive BCC→$E0, CMP/BCS→store CMP/BCC→store BMI-split: BPL/CMP/BCS 8
Sub_BCDC BMI → negative BCC→clamp, CMP/BCS→store CMP/BCC→store BPL/CMP/BCS (no BMI-split) 8
Sub_BFF2 BMI → negative BCS/BPL clamp (new variant) direct add, no clamp BMI-split: BPL/CMP/BCS 12
Sub_C2BF BMI → negative BCS/BPL clamp (same as BFF2) raw copy + direct add raw copy + BPL/CMP/BCS (no BMI-split) 12

The BPL/BMI switch on C5 is especially counterintuitive: Sub_B788, Sub_B8CA, and Sub_BA65 use BPL to reach the positive (C5<$80) path, while Sub_C73A, Sub_BCDC, and Sub_BFF2 use BMI to reach the negative (C5≥$80) path. Same logical signal, opposite dispatch direction.

Sub_BFF2 and Sub_C2BF together confirm two patterns:

  1. BMI-split tracks the low-state family — now confirmed across both type pairs. Sub_BFF2's positive path (low-state, types 2/3+) uses the BMI-split (BPL → skip, CMP #$E0, BCS → skip, else LDA #$E0) — same as Sub_BA65 (low-state, type 1). Sub_C2BF's positive path (high-state, types 2/3+) uses NO BMI-split, reading raw table ($4804,X → $4BC4,X) before applying BPL/CMP/BCS — same as Sub_BCDC (high-state, type 1). The correlation holds across TWO type pairs:
  2. High-state (Sub_BCDC type 1, Sub_C2BF types 2/3+): no BMI-split, raw table copy in Y path

  3. Low-state (Sub_BA65 type 1, Sub_BFF2 types 2/3+): BMI-split, reads staging Y directly

  4. BCS/BPL clamp ordering is shared between low-state and high-state C6≠0 paths. Sub_C2BF's C6≠0 path uses BCS → #$E0 / BPL → keep (carry first, sign second), identical to Sub_BFF2's C6≠0 path. This ordering is distinct from the earlier routines (Sub_BCDC, Sub_B8CA) which used BCC→clamp / CMP #$E0 / BCS→store. There are now three distinct carry/sign clamp orderings across the matched set.

disasm.py — M-flag linear-decoder trap at loop-exit branches

Symptom: the decoder generates wrong M-state (and thus wrong instruction widths) for code immediately after a conditional branch that exits a loop containing REP #$20.

Root cause: when a BEQ/BPL/etc. exits a loop, the decoder queues the branch target (correct state) but continues linearly through the loop-continuation code. If that code contains REP #$20, the decoder's running M-flag becomes 0. When the linear scan then reaches the branch target address, it visits it with M=0 instead of M=1, and the queued correct-state entry is skipped (already-visited check).

Affected code: any loop where SEP #$20 is in the body but REP #$20 appears in the loop-continuation tail before the back-branch. Hit in Sub_C73A (sessions 11) and Sub_B8CA (session 12).

Fix (tools/disasm.py, branch handling): instead of falling through linearly after a conditional branch, terminate the linear scan and queue the fall-through as a separate work item. Both the branch-taken and fall-through paths then start from the correct M-state captured at the branch point, with neither able to contaminate the other.

Implication for manual decoding: if using an un-patched disasm.py output near a loop exit, manually re-derive M-state from the actual execution entry rather than trusting the disassembler's annotation. The error is always at the branch target of a BEQ/BPL that exits a loop, and the symptom is an immediate-mode instruction being decoded at double width.

Sprite System Overview

The sprite subsystem is a fully matched, self-contained cluster spanning fourteen routines across two address ranges in bank $C0 ($B271–$C989 and $E9E2–$EA41). Every callee within the cluster is now matched; the cluster has no external call targets except matched helpers.

Entry point and frame trigger. Every frame, VBlankHandler tail-calls PostVBlank ($C0:B271). PostVBlank resets the OAM DMA channel registers, then walks the sprite descriptor table at $7E:0E00 (63 entries, 2 bytes each). For each active entry it calls Sub_B309 ($C0:B309), following chain-link bytes to handle multi-sprite objects, then fills any remaining OAM slots with Y=$E0 to park them off-screen.

Render dispatch (Sub_B309). Sub_B309 is the main per-sprite entry. It first calls Sub_B701 as a gate: if the gate sets carry, the sprite is not ready and Sub_B309 returns immediately. If the gate clears carry, Sub_B309 reads the sprite type from $7E:1201,X (bits 0–1: type 0/1/2/3+), then reads range selection bits (bits 2–3 of $7F:0F80,X) to pick one of three OAM write-heads ($0181/$0185/$0189) and WRAM destinations ($01DB/$01DD/$01DF). It uses the DP=$2100 trick (PHD/LDA #$2100/TCD) to alias PPU registers into the direct page. After writing the OAM position bytes from the $7F:4F00 staging buffer, it iterates the palette copy loop (4/8/12/24 iterations depending on type), reading from $7F:4BC0 into WMDATA ($2180 via DP trick).

State gate (Sub_B701). Sub_B701 dispatches on sprite type and reads the state byte at $7E:1B00,X. State zero means inactive (carry set, skip). A positive state below the per-type threshold means partially initialised (carry set, skip). A positive state at or above the threshold triggers the high-state init path. A negative state (bit 7 set, bits 0–6 non-zero) triggers the low-state init path. A state of exactly $80 means fully initialised and triggers rendering.

Init helpers — high state and low state. The distinction is the most important structural insight in the cluster. High-state init reads raw animation data from ROM/WRAM tables and copies it into the $7F:4B00 staging buffer before applying Y clamping. Low-state init reads Y data directly from the staging buffer that the previous high-state pass already populated. This produces different clamp code in each family.

For types 0: Sub_B8CA handles init (high-state only; type 0 has no separate low-state init path — Sub_B788 is its renderer). For type 1: Sub_BCDC is high-state init (raw table → staging, BPL/CMP/BCS positive path, no BMI-split); Sub_BA65 is low-state init (reads staging, BMI-split on positive path). For types 2/3+: Sub_C2BF is high-state init (same BPL/CMP/BCS pattern as BCDC, no BMI-split); Sub_BFF2 is low-state init (BMI-split, identical pattern to BA65). The BMI-split thus tracks exactly with the low-state family across both type pairs, and its absence tracks with the high-state family.

Pass 2 init (mark-and-exit). After each init helper runs, Sub_B701 calls a pass-2 helper to record the sprite's slot in the $7E:0BC0 entity table. Sub_E9E2 handles type 0 (4-entry search, marks 1 byte). Sub_E9FF handles type 1 (3-entry search, marks 2 bytes: $0BC0,X and $0BC1,X). Sub_EA1F handles types 2/3+ (2-entry search, marks 3 bytes: $0BC0,X, $0BC1,X, $0BC2,X). The pattern is consistent: the number of OAM slots a type uses equals the number of table bytes marked.

Renderers. Sub_B788 is the type 0 renderer (8-bit sprites, single OAM entry). Sub_C73A is the type 3+ renderer (6-tile sprites, 24 OAM entries); it calls Sub_C6E7 six times, once per tile group, to pack X-position overflow bits into the OAM attribute byte. Types 1 and 2 do not have separate renderer routines in the matched cluster; their render path is served by Sub_B309's direct OAM write.

Y-clamp ordering summary. Three distinct branch orderings appear. Type 3+ (Sub_C73A) uses BCS/BPL: carry first, sign second, because large tile X coordinates enter the clamp path with carry already set. High-state init routines (Sub_BCDC, Sub_C2BF) use BPL/CMP/BCS on the positive path: sign first, then compare against $E0, then carry — no BMI-split because the raw table value is always bounded. Low-state init routines (Sub_BA65, Sub_BFF2) add a BMI-split on the positive path: BPL skips the clamp check entirely for small positive Y values, because the staging buffer can hold values that the high-state pass already bounded, but a second clamp pass may still encounter borderline cases where an intermediate BMI branch saves work.

Mode handler cluster ($C0:0D78–$16DB) — door/switch tile-opening dispatch

Five mode-specific scroll-map update handlers live in a contiguous block starting at $C0:0D78 and ending at $C0:16DB (just before the default handler at $16DC). These handlers implement the tile-opening animation for doors and interactive switches on the map: each frame, Sub_0C76 dispatches to the appropriate handler based on the current animation mode, the handler advances the $7E:3000 layer-state table, computes VRAM tilemap write indices corner-by-corner, and triggers an SPC audio cue. All five handlers share a two-phase structure:

Phase 1 — Mode-table prologue. Increments selected entries in the $7E:3000 layer-state table using LDA.l $7E3000,X / INC A / STA.l $7E3000,X. The number of entries updated scales with the handler: E6=2, EC=4, EE=4, FA=6, FC=6. All but E6 include at least one REP #$20; TXA; SEC; SBC #$0100; TAX; SEP #$20 block to index $100 rows back in the table. The prologue ends with JSR Sub_1B90 (SPC audio command $19) and a write to dp:$60.

Phase 2 — VRAM index computation. A REP #$20 block loads the scroll bases from $1D0A/$1D0E into dp:$DB/$DD. Then N passes × 4 corner iterations call JSR Sub_1B36 to compute a tilemap word index (col×32 + row with $0400 wrap) for each of the four corners of a 2×2 tile block, offset by ADC $1D7C, and store the result into a $09CA–$09F8 VRAM slot.

Pass structure per corner block (62 bytes, invariant across all handlers): 

; Corner 1: (row, col) — X=col_idx, Y=row_idx already set
JSR Sub_1B36  →  CLC / ADC $1D7C  →  STA $09CA
; Corner 2: (row+1, col)
TYA / PHA / INC / AND #$003F / TAY / TXA / JSR Sub_1B36  →  CLC / ADC $1D7C  →  STA $09CC
; Corner 3: (row, col+1)  — restores pushed row
PLY / TXA / INC / AND #$001F / TAX / JSR Sub_1B36  →  CLC / ADC $1D7C  →  STA $09CE
; Corner 4: (row+1, col+1) — uses current Y/X from corner 3
TYA / INC / AND #$003F / TAY / TXA / JSR Sub_1B36  →  CLC / ADC $1D7C  →  STA $09D0

Row/col base selection per handler:

Handler Row bases Col bases Passes VRAM slots
ModeE6_Handler $5B $5C, $5C−1 2 $09CA–$09D0, $09D2–$09D8
ModeEC_Handler $5B, $5B+1 $5C, $5C−1 4 $09CA–$09E8
ModeEE_Handler $5B−1, $5B $5C, $5C−1 4 $09CA–$09E8
ModeFA_Handler $5B, $5B+1 $5C, $5C−1, $5C−2 6 $09CA–$09F8
ModeFC_Handler $5B−1, $5B $5C, $5C−1, $5C−2 6 $09CA–$09F8

Pass 1 LDX anomaly. The compiler emits LDX $5B; TXA (3 bytes) instead of LDA $5B (2 bytes) for the row setup of every handler's first pass. All subsequent passes use LDA $5B normally. In Mode-EC and Mode-FA (positive row handlers), pass 1 has no additional modifier. In Mode-EE and Mode-FC (negative row handlers), pass 1 adds DEC A between TXA and ASL.

Tail. All handlers except ModeFC end with SEP #$20; LDA #$10; TSB $5F; BRL <raw_offset> to reach the default handler at $16DC. ModeFC sits immediately before $16DC and falls through without a BRL (tail is only SEP #$20; LDA #$10; TSB $5F).

dp:$60 value encodes the scroll update width: $00 = 2-entry (E6), $01 = 4-entry (EC/EE), $02 = 6-entry (FA/FC). This value is consumed by the default handler or the SPC audio subsystem.

DefaultHandler ($C0:16DC–$18D8)

The DefaultHandler is the sixth arm of Sub_0C76's per-frame dispatch. It occupies 509 bytes immediately after ModeFC_Handler and is architecturally distinct from the five named mode handlers in several concrete ways.

Different layer-state variables. The named handlers (E6/EC/EE/FA/FC) read their layer-state index from dp:$5B/$5C. DefaultHandler reads from dp:$5D/$5E. This is not a convention difference — Sub_0C76 stores separate index values in each pair, and the handler uses whichever pair matches its role.

Different VRAM slots. The named handlers write their computed tilemap word-indices into the $09CA–$09F8 range. DefaultHandler writes to $09B2–$09B8 (four slots, one pass of 4 corners). The computation formula is identical (Sub_1B36 + ADC $1D7C), only the destination addresses differ.

Different SPC callee. The named handlers call Sub_1B90 with dp:$FC as the audio argument. DefaultHandler calls Sub_1BA7, a 4-byte wrapper that loads dp:$FB instead and then branches into Sub_1B90's body at the second instruction. The parameter register ($FB vs $FC) selects a different SPC command argument from the audio table.

No mode-table prologue. The named handlers begin by incrementing selected entries in the $7E:3000 layer-state table (2–6 entries depending on mode). DefaultHandler has no such prologue. Its VRAM section is conditional: it only runs if dp:$17 bit 1 is set, and only advances the layer-state entry if it reads $FE or $E0 (terminal values).

Bit-5 transition loop. After the optional VRAM section, DefaultHandler checks dp:$17 bit 5. If set, it clears it and enters a busy-loop: JSR $885A (a large unmatched frame-work routine) followed by JSR $00BF (VBlankHandler), repeating until dp:$38 reaches zero. After the loop it dispatches on dp:$45 (values 1–4) to one of four transition sub-modes, each calling a mode-specific renderer with DP temporarily set to $1D00, then tail-calling Sub_EC60.

Bit-0 scene-swap. If bit 5 was clear, DefaultHandler checks bit 0 of dp:$17. If set, it calls a scene-state probe at $024C. A carry-clear result triggers a full scene-swap sequence (JSL $C02C41, JSL $C10000, JSR $0B64/$0B75, etc.); carry-set takes a quick-clear path and tail-calls the $00EB fragment.
